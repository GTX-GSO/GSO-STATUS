## GSW 1.0.0

2026-10-22。定为正式版，上一版是 0.1.21。

- **开机自启**（新文件 `gsw/Autostart.cs`）：写当前用户的注册表 `Run` 项，内容是本程序和它当前使用的配置文件。GSW 本身不需要管理员权限，所以不用计划任务；这一项会出现在任务管理器的“启动应用”里。
  - 托盘菜单新增“开机自启”勾选项。只有这一项指向的正是当前这份程序和配置时才显示为勾选；指向别处的副本，或在任务管理器里被禁用，都算未开启。在托盘里重新打开会清除任务管理器的禁用标记。
  - 命令行：`--enable-autostart`（配置能正常加载才会写入）、`--disable-autostart`。
- **安装脚本** `scripts/install-gsw.ps1`（发布包里同名）：
  - 装到 `%LOCALAPPDATA%\Programs\GSO STATUS WIN`，不需要管理员权限。
  - 先通过停止事件让正在运行的 GSW 退出（不动提权的 CPU 传感器工作进程）；复制后核对 `GSW.exe` 哈希。
  - 配置：用 `-Config` 指定时会替换已装配置；不指定时保留已装的 `gsw.json`；首次安装取项目的 `config/gsw-nas.json`。都没有时只放入样例配置，不启动。
  - 默认开启开机自启并立即启动；`-NoAutostart`、`-NoStart` 可关闭这两步。
- **GPU 数据自动恢复**（`gsw/Nvml.cs`）：原来 NVML 只在启动时初始化一次。开机自启时如果显卡驱动还没就绪，或之后驱动重置、更新导致句柄失效，GPU 数据会一直缺失到重启 GSW。现在取不到 GPU 时每 30 秒重试；读数返回“未初始化”“参数无效”“GPU 丢失”时放掉旧句柄，等下次重试。
- Codex 只读接口上报的客户端版本改为读取程序版本，不再写死 `0.1.0`。
- **发布包** `artifacts/GSO-STATUS-WIN-1.0.0-win-x64.zip`：`package-release.py` 不再把带写令牌的 `gsw.json` 打进去，改为附带 `gsw.example.json` 和 `install-gsw.ps1`，打包后会检查。
- `启动NAS模式.cmd` 优先启动已安装的 GSW。`start-local.ps1`、`stop-local.ps1`、`esp-idf-env.ps1` 加上 UTF-8 BOM：它们含中文，Windows PowerShell 5.1 读没有 BOM 的脚本会按 ANSI 解码。
- **代码检查**：托盘（资源管理器未就绪或重启时会重新加图标）、CPU 传感器共享内存与提权隔离、磁盘计数器、RTSS 与 PresentMon（启动前校验哈希）、Codex/Claude 观察器都过了一遍，除上面两处外没有发现问题。
- **验证**：编译 0 警告；GSW 测试 25 项通过，新增开机自启测试（在临时注册表子键上测开启、关闭、另一份副本、任务管理器禁用、相对路径拒绝，测完删除）；托盘冒烟测试通过；本机已安装 1.0.0 并开机自启，日志“已连接”，CPU 传感器工作进程正常拉起。还没有经过一次真正的重启来验证。
- 未改动：提权的 CPU 传感器工作进程仍是上次安装的版本，协议没有变化。要更新它，需要以管理员身份运行 `install-cpu-sensor.ps1`。

## GSS 1.0.0

2026-10-20。定为正式版。相对 0.7.36：打开详情页到首帧 93→约 88ms，拖动卡片条约 21.5→23 帧/秒，开始拖动的卡顿 56→35ms。新板上的完整数据见[性能排查](性能排查.md)的“2026-10-20 第三轮”。

- **点击控件不再滑动卡片条**：这是缺陷修复。LVGL 的按钮、滑块、开关等控件会在获得焦点时把自己滚到可见位置；本项目没有焦点组，每次按下都会让被按的对象获得焦点。卡片条又是左对齐吸附，于是 NET 在中间时点 Clash 按钮，NET 会被滚到最左边。现在每次按下时、在 LVGL 处理焦点之前，先清掉屏幕上所有对象的“获得焦点时滚动到可见”（`real_ui.inc` 的 `no_scroll_on_focus`）。Clash 界面测试改为先把 NET 翻到中间再点；关掉这个修复时，该测试和新增的自检项都会失败。
- **拖动时 PPA 只转换卡片条区域**（`main/gss_present.h`）：脏区超过整屏 60% 时，转换这些区域的外接矩形，不再转换整屏，侧栏不用重转。拖动帧 PPA 23.8→19ms。主机测试 `tests/present_test.c` 新增一项。
- **冻结卡片条时先拍可见卡片**（`strip_freeze.inc`）：拖动方向上的邻卡和反方向的邻卡分别推迟到之后两次定时器处理时再拍，开始拖动的卡顿 56→35ms。邻卡拍好之前暂时实时渲染。
- **GAME 页开场面板改为实时绘制**：不再拍 1032×420 的快照，打开 GAME 页 73→19ms。
- **HOME 详情页只为实际存在的设备建卡片**：不再一次建满 16 个。这台板子接了 13 个设备，所以只省了约 12ms（109→97ms），剩下的时间花在建卡片和填内容上，未再优化。
- **整理**：删除触摸诊断日志；`main.c` 的引脚改用 `gss_board.h` 的定义（新增翻转键 `GSO_FLIP_KEY_GPIO`），开机日志 `BOARD_READY` 打印实际的 DSI 和像素时钟（60MHz）；更新 `gss_board.h` 中关于 C5 和加速度计“尚待实物验证”的过时注释；`scripts/build.ps1` 写入的模拟器版本号同步；打包脚本和 `flash-firmware.ps1` 默认串口改为新板的 COM5。
- **验证**：
  - 模拟器自检 30 项通过。
  - 共享模型、链路、水平仪、出帧、亮度、快照解析测试通过；Clash 界面、Clash 客户端、Wi-Fi 凭据、HOME 投递、HOME 回环（含滑块与按钮）、字体覆盖测试通过。
  - GSN 和契约的 Go 测试及 vet 通过；GSW 24 项测试通过。
  - 正式固件已烧录 COM5：开机、GSN 快照正常，内部 RAM 约 188KB 稳定。发布包 `artifacts/GSS/GSO-STATUS-1.0.0-gss.bin` 已打好。

## GSS 0.7.36

2026-10-20。性能第二轮：导航到首帧 129→93ms，拖动卡片条约 14→21 帧/秒，开始拖动时的卡顿 135→56ms。逐项板上数据见[性能排查](性能排查.md)的“2026-10-20 第二轮”。

- 主循环（`main/main.c`）：不再每轮固定睡 5ms，而是睡到 LVGL 下一个定时器到期（1–5ms）。动画期间一帧比 16ms 的刷新周期长，原来的 5ms 全是空等。
- 拖动快照（`simulator/transition_cache.inc`、`strip_freeze.inc`）：卡片条的快照改成显示格式（板上 RGB565）的不透明图，生成时先铺上背景色，圆角处直接带背景，贴图只是逐行复制、不再做透明混合。开机过场面板仍用 ARGB8888，因为它要滑过其他内容。
- 程序从 PSRAM 执行（`CONFIG_SPIRAM_XIP_FROM_PSRAM`，写进 `config/gss-hosted-reference.defaults`）：代码和字体从 200MHz HEX PSRAM 读，不再从 80MHz DIO flash 读。多占 5.8MB PSRAM，开机约慢 0.3 秒，内部 RAM 187→177KB。
- 出帧与渲染重叠（`main/main.c`）：LVGL 改用两块绘制缓冲；flush 只把这一帧交给新的 `gso_present` 任务（core1，优先级 5），由它做 PPA 旋转和换帧，LVGL 同时渲染下一帧。多占 1.16MB PSRAM。
- 基准开关（`GSO_GSS_BENCHMARK`）新增：建页面耗时与帧间隔（`BENCH3`）、模拟手指拖动卡片条 8 次（`BENCH_DRAG`）、快照冻结耗时（`BENCH_FREEZE`）。
- 试过但没有保留：GSN 快照轮询复用 HTTP 连接，请求耗时 35→33ms，在误差内（时间花在 GSN 生成和传 28KB 上，不在建连接），已撤销；LVGL 9.4 自带的 PPA 绘制单元，代码不可用（总是画在图层左上角、每个任务同步整块缓冲），没有启用。
- 验证：模拟器自检 29 项通过；正式固件已烧录 COM5，开机、Wi-Fi、GSN 快照正常，内部 RAM 约 177KB 稳定。用户目测正常：拖动时卡片圆角和背景融合，翻页和打开详情没有撕裂或花屏。以后显示链路出问题时，把 `main.c` 换回单绘制缓冲、flush 内直接做 PPA 的写法即可（0.7.35）。

## GSS 0.7.34 / 0.7.35

2026-10-20。触摸更顺、点击不再误触发滑动；自动亮度以书房 100 lx 为满亮度。

- 触摸（`main/main.c` 的 `pointer_read`）：控制器只在触摸变化时发中断，原来按住或拖动时靠中断读取，拖动发顿，抬手最多 500ms 后才被发现。现在按住时每 15ms 轮询，读不到手指要连续两次才算抬起（I²C 偶发空读不再被当成抬起），两次轮询之间位置跳超过 400px 的当噪声丢弃；LVGL 开始滑动的阈值由默认 10px 提到 24px，输入读取周期 10ms。点击 Clash 切换和 HOME 控件时误触发卡片条滑动，主要来自这几处，未改自动吸附本身，等用户试手感。
- 自动亮度（`shared/gso_brightness.c`）：曲线改为 0/10/50/100 lx 对应 15/30/60/100%，屏幕本身不亮，书房 100 lx 即满亮度。`tests/brightness_test.c` 按新曲线更新并通过（31 lx 目标约 46%）。
- 验证：模拟器自检 Overall PASS，亮度模型测试通过，`verify-shared-code` 通过，0.7.35 已刷入 COM5。
- 限制：触摸手感和误触发是否消失需要你实测；亮度只验证了模型，实际光照下的观感未测。

2026-10-20。水平仪小球改为停在偏低的一侧；本机状态 CPU 假读数和写死的内存速率修复。

### CPU温度与功耗间歇空值

真实观察捕获到：共享帧flags=3且仍有有效温度/功耗，但原始采样间隔超过3秒，GSN快照收到GSW上报的cpu_sensor_stale空值。因此前一版3秒瞬时空值过滤不足以覆盖本机硬件扫描间隔。

GSW0.1.14将传感器帧及独立指标缓存的最大年龄统一为10秒，始终使用原始采样时间；重复读取旧帧或收到非法值不会续期，温度和功耗分别过期。持续无有效样本超过10秒仍为空。该调整不改变GSW网络来源的3秒过期策略，也不把传感器数值估算或补零。独立CPU传感器任务未替换，正常采集端已更新。

确定性测试覆盖4.5秒有效扫描间隔、10秒过期、单项更新时间不同、NaN/负功耗和读写中的共享帧。更新前60次回读温度/功耗各出现6次空值，原因均为cpu_sensor_stale；更新后120秒、120次回读均无空值，其中8次原始帧年龄超过3秒，最高5.562秒。记录见artifacts/verification/cpu-source-filter-0.1.14.json；短测通过不能替代长期观察。
