## 仅需的文件与设置

主配置位于 `\\192.168.124.14\hdd0\GSN\config\gsn.json`；镜像位于 `\\192.168.124.14\hdd0\我的镜像`。用户已授权 `scripts/sync-nas.ps1` 直接同步：先本地备份旧主配置，再校验上传 SHA256，不覆盖 `router-login.private.json`。

1. 在 NAS 管理界面停止旧 GSN，导入最新 ARM64 镜像并替换或重建容器。
2. 选择 **host** 网络，不配置端口映射。主配置 listen 为 `0.0.0.0:2780`。
3. 挂载实际宿主机路径 `/hdd0/GSN/config` 到 `/app/config`，读写；保留默认入口。按实际管理界面设置重启策略及日志轮转 10MiB × 3。
4. 启动后访问 `http://192.168.124.14:2780/healthz`，应返回 ok。Windows 客户端地址不变；readyz/snapshot 使用读取令牌，GSW 使用独立写入令牌。

容器导入、替换、启动与回滚由用户操作；SMB 同步脚本只交付文件。回滚使用保留的旧镜像与本地备份主配置，保留私有凭据。128MiB 内存上限只是候选，需实际峰值验证后确定。

## 路由器登录与日志

凭据从同目录 `router-login.private.json` 读取，不写入文档或普通日志。自动提交路由器密码表单，Cookie 仅在内存，会话失效自动重新登录；错误密码停止重复提交，修改私有文件后再试，瞬时故障冷却重试。

## 可选 Docker 状态（0.1.9）

注意：socket挂载标记只读并不能限制Docker API操作权限；本程序仅发起GET inspect请求，socket本身仍是高权限入口。当前没有自动增加任何socket挂载。

## NAS存储容量（0.1.20）

两块存储容量由GSN读取，显示在NAS卡片和NAS详情页（0.1.26起不再放在NET详情页）。主配置增加（最多2项）：

```json
"storage":[{"label":"eMMC","path":"/app/config"},{"label":"HDD","path":"/app/usb3"}]
```

容器内任何目录都会报告它所在卷的容量，不读文件名和内容。`/app/config`已是`/hdd0/GSN/config`的挂载，直接代表hdd0；usb3需要在NAS管理界面为容器额外挂载usb3上的一个目录（只读即可）到`/app/usb3`。未配置或读取失败时屏上显示“未接入/容量不可用”，不影响其他数据。配置文件上限4096字节，加入后请确认没有超限。GSW端无需配置：它获知GSN支持后会自动上报客户端在线与当日token。

## NAS主机状态（0.1.33）

NAS卡片显示GSN所在主机的CPU占用、内存、SoC温度（快照里另有GPU温度），一块机械盘（HDD）的温度、工作状态与健康，以及eMMC和HDD的占用和读写速率。CPU/内存/温度/读写速率读`/proc`和`/sys`（容器里看到的就是宿主机），不需要配置；硬盘温度和健康需要GSN容器**特权运行**且以root身份（非root打不开`/dev/sda`；导入镜像后请确认容器没有覆盖运行用户），并在主配置里指定设备：

```json
"nas":{"disk":"/dev/sda","disk_read_asleep":false,"disk_interval_seconds":600}
```

- `disk`只接受`/dev/sda`这类整盘设备；不写`nas`段则整张NAS卡片不出现。`emmc`（默认自动找第一块`/dev/mmcblkN`）指定要统计读写速率的eMMC，只读内核计数器，不碰设备。
- **读硬盘信息不会把休眠的机械盘叫醒**：只在盘一定转着时才读SMART。依据是内核的块设备计数`/sys/block/sda/stat`——两次采样之间有读写完成就说明盘在转，此时才发一次只读的SMART READ DATA（温度和健康在同一次读里取得）；读这个计数文件不碰盘。没有读写时不发读数命令，上一次的温度最多沿用30分钟，之后温度显示为“空闲”。
- `disk_read_asleep`（默认假）：真则在休眠或状态未知时也读温度，读取可能唤醒硬盘：读取耗时2秒以上，或读完硬盘立即答“运行中”，都算作我们自己造成的一次唤醒并计入今日次数，用来判断硬盘能否凭缓存回答。**日常不要打开**：每次读取都会重置硬盘的待机计时，读得越勤盘越难睡下去。
- `disk_interval_seconds`（60–3600，默认600）：两次读SMART的最短间隔。任何命令都会重置硬盘自己的待机计时，间隔越长越不影响它进入休眠。
- `disk_io_only`（默认假）：真则除上面那次SMART读取外**不给盘发任何命令**；假则另外每分钟问一次ATA CHECK POWER MODE（规范上不唤醒硬盘）。这个回答不完全可靠，GSN在盘刚有读写完成时不采信“休眠”。
- `disk_sleep_seconds`（60–3600，默认300）：硬盘自己的空闲休眠时间。得不到明确的电源状态时，按“最后一次读写完成后这么久休眠”推断。
- `utc_offset_minutes`（默认480，北京时间）：决定“今日”从哪里算起。
- 硬盘工作状态`nas.disk_state`为`active`（已唤醒）、`standby`（已休眠）或`quiet`（尚未判断出）；`nas.disk_wake_count_today`是今日由休眠变为唤醒的次数。计数只保存在GSN进程内存里：容器重启归零，过本地零点清零。
- 硬盘健康（`nas.disk_health`）取自同一次SMART读取：`good`良好；换过扇区或有待处理扇区为`watch`（需要留意）；SMART整体状态判为失败、待处理扇区不少于10个或已换扇区不少于100个为`bad`（有风险）；两个计数都读不到为`unknown`。同时给出通电小时数、已换扇区、待处理扇区、接口通信错误（CRC）、启停次数和磁头加载次数（`nas.disk_power_on_hours`、`disk_reallocated_sectors`、`disk_pending_sectors`、`disk_crc_errors`、`disk_power_cycles`、`disk_load_cycles`）。屏幕上NAS详情页的“硬盘健康”页用白话呈现这些数字，健康为`watch`/`bad`时左侧栏常驻提示。接口通信错误是历史累计值，只在它继续增长时才说明线缆或接口有问题。
- “启停次数”是整机开关机的累计次数；机械盘休眠后唤醒时增加的是磁头加载次数。

## 拓竹打印机状态（0.1.21）

PRINT卡片显示拓竹打印机（已用A1 mini确定接口，其他P1/X1系列字段相同但未实测）的任务进度。打印机侧需要：开启**局域网模式（LAN Only）**，并开启**开发者模式**（保持本地MQTT通道开放）；记下打印机屏幕上的IP地址和访问码。访问码固定，不会定期更新，只在你开关局域网模式时重新生成；认证失败（屏幕显示“未连接”、GSN快照里`printer.source.last_error_code`为`printer_auth_failed`）时先核对屏幕上的访问码。

主配置增加：

```json
"printer":{"host":"192.168.1.50","access_code":"在打印机屏幕上查看"}
```

`host`写IP或主机名（不带端口和协议），`access_code`为4–32位字母数字；序列号不用配置：打印机的MQTT只接受它自己的主题（订阅通配符会被直接断开），GSN从打印机TLS证书的通用名读取序列号；必要时仍可手动写`"serial"`。访问码只放在这份私有配置里，不会进入快照、日志或发布包。GSN以只读方式订阅`device/+/report`，另外每个会话和每15分钟发一次`pushall`请求完整状态，从不发送控制命令。打印机使用自签证书，连接是加密的，但不校验证书，只靠IP和访问码识别对方，所以请确认容器只在可信局域网内访问它。配置文件上限仍是4096字节，加入后请确认没有超限；容器需要能访问打印机的8883端口。

模型缩略图（0.1.23）：GSN另外通过打印机的FTPS（990端口，同一访问码）读取任务的3mf（从Studio经局域网发送的在存储根目录，文件名同`gcode_file`；其他在`/cache`）开头约256KB，取出里面的模型图，裁到模型、缩成120×120后缓存，每个任务读一次（不下载整个文件，实测约2秒；打印机的FTP不支持断点续传，所以只读开头）。文件已不在`/cache`或读取失败时不显示缩略图，隔45秒重试。容器需要能访问打印机的990端口。

屏上行为：卡片在没有配置打印机时不显示；配置后默认排在最后，打印中（含准备中、暂停）自动移到VIBE后面，完成或失败后再保持10分钟靠前；打印机关机或失联超过90秒显示“未连接”。点击卡片进入详情页看进度、剩余时间、层数、喷嘴和热床温度、错误代码（十六进制，无错误显示“无”）。

车辆（0.1.25）：`ha.car`段绑定HA零跑集成的实体并决定是否开放控制，字段见[HOME接入与控制](HOME接入与控制.md)的CAR一节和`config/gsn-ha.example.json`。`actions`为空时只显示数据；写成`["lock","unlock","press"]`才开放锁车、解锁、刷新，且需要已配置`home_control_token`。配置文件上限已从4096字节提到8192字节，0.1.23及更早的镜像读不了加入车辆后的配置，需先导入0.1.24镜像。
